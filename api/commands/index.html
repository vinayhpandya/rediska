    commands¶

    import "github.com/vinayhpandya/rediska/commands"

    Package commands implements every Redis command Rediska supports.

    Each command lives in its own file and registers a handler with Register from an init function. Dispatch looks the handler up and runs it; in cluster mode it first checks that this node owns the command's keys.

    All functions that touch data (Dispatch, DispatchBatch, DispatchPipeline) must run on the server's single dispatch worker goroutine, because the store is not safe for concurrent use.

    func CheckCluster¶

    func CheckCluster(cmd *Command) []byte

    CheckCluster reports whether this node may run cmd in cluster mode. It returns nil if so (or if cluster mode is off), otherwise the error reply to send instead: CROSSSLOT, CLUSTERDOWN or MOVED.

    The server package calls it while queuing commands inside MULTI. That happens on the connection's goroutine, not the dispatch worker, which is safe only because the cluster layout never changes after startup. Once slots can move at runtime, this must go through the worker or take a lock.

    func Dispatch¶

    func Dispatch(cmd *Command) []byte

    Dispatch runs one command and returns its encoded RESP reply.

    It replies with an error, without running anything, if the command is unknown or, in cluster mode, if its keys span several slots (CROSSSLOT), belong to no node (CLUSTERDOWN) or belong to another node (MOVED).

    For commands that can grow memory, and only when --maxmemory is set, it then evicts keys according to the policy, and replies with an OOM error without running the command if memory is still over the limit.

    Otherwise it runs the handler, and appends successful write commands to the AOF if one is set (see SetAOF).

    Dispatch must only be called from the dispatch worker goroutine.

    func DispatchBatch¶

    func DispatchBatch(cmd []*Command) []byte

    DispatchBatch runs the commands queued by MULTI when the client sends EXEC, and returns their replies wrapped in one RESP array.

    In cluster mode, all keys of all the commands together must be in one slot owned by this node. If they aren't, DispatchBatch returns that single error (CROSSSLOT, CLUSTERDOWN or MOVED) and runs nothing, so a transaction never runs halfway.

    func DispatchPipeline¶

    func DispatchPipeline(cmds []*Command) []byte

    DispatchPipeline runs each command in order and returns their replies concatenated back-to-back -- exactly as if each had been dispatched and written individually, one at a time. Unlike DispatchBatch (used for MULTI/EXEC, which needs one array-wrapped reply representing the whole transaction), pipelined commands each need their own independent, individually-parseable reply, so no outer array framing is added here.

    func IsKnownCommand¶

    func IsKnownCommand(name string) bool

    IsKnownCommand reports whether a command called name (upper case) has been registered. MULTI uses it to reject unknown commands when they are queued, rather than at EXEC.

    func KeysOf¶

    func KeysOf(cmd *Command) (keys []string, ok bool)

    KeysOf returns the key arguments of cmd. ok is false if the command has no key spec (i.e. it is unknown). Too few arguments just yields fewer keys; the handler itself reports the arity error.

    func Register¶

    func Register(name string, f HandlerFunc)

    Register adds a command. name must be upper case, since Dispatch looks commands up by their upper-cased name. Registering a name twice replaces the earlier handler. Command files call Register from their init function.

    func Replay¶

    func Replay(cmd *Command)

    Replay runs a command read back from the AOF at startup. Unlike Dispatch, it skips the cluster check and the memory check, and doesn't write to the AOF: everything in this node's AOF was already accepted by this node, so it must all be loaded back, even if the cluster layout has changed since. Unknown commands are ignored.

    func SetAOF¶

    func SetAOF(a *core.AOF)

    SetAOF makes Dispatch append successful write commands to a. Call it only after the AOF has been replayed at startup; otherwise every replayed command would be written to the file a second time.

    type Command¶

    Command is one parsed client request, such as SET name vinay.

    type Command struct {
    Name string // uppercased for case-insensitive lookup
    Args []string
}

    func ParseCommand¶

    func ParseCommand(decoded any) (*Command, error)

    ParseCommand turns a value decoded by core.Decode into a Command. The value must be a non-empty array of bulk strings; the first one becomes the upper-cased command name.

    type HandlerFunc¶

    HandlerFunc runs one command. args are the command's arguments without the command name, and the return value is the full encoded RESP reply.

    type HandlerFunc func(args []string) []byte

    type KeySpec¶

    KeySpec says which arguments of a command are keys, using the same scheme as Redis's command table. Positions index the full argv, where argv[0] is the command name itself:

    First: position of the first key (0 = the command takes no keys)
Last:  position of the last key; negative counts from the end, so -1
       means "the last argument"
Step:  distance between keys (1 = every argument in range is a key)

    Examples: GET k -> {1,1,1}; DEL k1 k2 k3 -> {1,-1,1}; OBJECT ENCODING k -> {2,2,1}.

    type KeySpec struct {
    First, Last, Step int
}
