    replication¶

    import "github.com/vinayhpandya/rediska/replication"

    Package replication copies a master's data to its replicas.

    A replica connects to its master's client port and sends SYNC. The master then sends it two things over that connection, in one ordered stream of commands:

    • a snapshot: every key, as the command that recreates it (see store.SlotCommands), copied one slot at a time, and
    • every change made since, as the same entries the AOF records.

    The snapshot is copied a few slots at a time, between client commands, so clients never wait for the whole dataset to be copied. Copying and changes stay consistent through one rule: a change is sent to a replica only if its slot has already been copied to that replica. A change to a slot that hasn't been copied yet is skipped, because the slot will be copied later with the change already in it. This works because in cluster mode every command's keys are in one slot.

    Variables¶

    BatchKeys and BatchBytes bound one copying step, so that it never holds up clients for long: a step stops once it has copied about BatchKeys keys or BatchBytes bytes, whichever comes first. Bytes matter because one 10 MB value is one key, but far from a cheap one. A step always copies whole slots (see the package comment), so a slot bigger than this is still copied in one step. Variables so tests can make copying take many steps.

    var (
    BatchKeys  = 1000
    BatchBytes = 1 << 20
)

    Default is this node's Master.

    var Default = NewMaster()

    func (*Link) Run¶

    func (l *Link) Run(ctx context.Context, flush func() bool, apply func([][]string) bool)

    Run keeps this node a copy of the master until ctx is cancelled. Each time it connects, it sends SYNC, then flush must clear this node's data, and apply must apply the commands that follow, in order: one command at a time, or a whole MULTI/EXEC block at once. flush and apply hand their work to the dispatch worker; they return false if the server is shutting down.

    Every connection starts from an empty store and a full copy, so if the connection drops, the replica simply connects again.

    func (*Link) Up¶

    func (l *Link) Up() bool

    Up reports whether the replica is connected to its master and receiving data. INFO replication shows it as master_link_status. Safe to call from any goroutine.

    type Master¶

    Master keeps track of the replicas connected to this node. Everything except a replica's queue belongs to the dispatch worker: the methods below must only be called there, except Serve.

    Count returns how many replicas are connected. Worker only.

    func (*Master) Feed¶

    func (m *Master) Feed(e Entry)

    Feed sends one change to every replica that already has e's slot. Worker only.

    func (*Master) FeedTransaction¶

    func (m *Master) FeedTransaction(entries []Entry)

    FeedTransaction sends the changes of one MULTI/EXEC to every replica, wrapped in MULTI and EXEC so the replica applies them all at once. Each replica gets only the entries whose slots it already has; one that has none of them gets nothing. Worker only.

    func (*Master) Serve¶

    func (m *Master) Serve(ctx context.Context, conn net.Conn, run func(func()) bool)

    Serve feeds the replica on conn, which has just sent SYNC, until it disconnects or ctx is cancelled. It runs on the connection's goroutine; run must run a function on the dispatch worker and wait for it to finish, returning false if the server is shutting down.
